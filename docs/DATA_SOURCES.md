# ライブデータ調査・接続手順

調査日: 2026-10-13。実際のHTTP取得と公式仕様を確認した。取得件数は受信状況と時刻により変わる。

## 現在の実装

| レイヤー | 標準の取得元 | データの意味・範囲 | 更新・制限 |
| --- | --- | --- | --- |
| 航空機 | adsb.lol、キー不要 | 地域内のADS-B受信位置。半径最大250海里、受信局のない地域は欠測 | 中心0.1度・半径5海里単位の共有210秒キャッシュ・取得枠、450回/日の上限。古い位置報告は除外 |
| 衛星 | CelesTrak OMM、キー不要 | 公開軌道要素からSGP4で予測した位置。ライブの位置テレメトリーではない | 永続キャッシュを最低2時間保持。非200・失敗時は自動取得を停止。キャッシュ24時間、軌道要素14日を超えるものは非表示 |
| 雲 | Open-Meteo GFS、キー不要 | 地域9地点、1000/925/850/700/500/300 hPaの予報雲量とジオポテンシャル高度。観測した雲の実体ではない | 30分キャッシュ、全体2秒間隔、400回/日、同時取得4件以下 |
| 雨 | RainViewer、キー不要 | 観測された降水レーダーを雨粒に変換。雨の柱の高さは近隣の予報雲高度を使う描画上の推定 | メタデータ10分キャッシュ。雲の高度を降雨強度から捏造しない |
| 船舶 | Fintraffic、キー不要 | フィンランド周辺・バルト海の受信局が対象。要求円内のClass A、漁船は対象外 | 全件の共通60秒キャッシュ、クライアントも60秒間隔。`timestampExternal`のエポック時刻で5分を超える報告を除外 |
| 公開カメラ | Fintraffic、キー不要 | 要求円内のフィンランド公式気象カメラ。動画ではなく、おおむね10分更新の静止画 | 全地点カタログ1時間キャッシュ、取得も1時間間隔。画像取得失敗時は配信元リンクを表示 |

デモモードは従来の決定論的シミュレーションを保持する。ライブモードで取得に失敗したレイヤーへデモの物体を補充しない。サイドバーの「取得元・更新時刻を確認」で各レイヤーの取得状態を確認できる。カメラの取得時刻は地点カタログの取得時刻であり、写真の撮影時刻ではない。

衛星の軌跡・選択中の軌道は、航空機とは独立したサイドバーのスイッチで切り替える。ラベルをオフにすればISS・天宮の常時ラベルも表示しない。選択時の詳細・ホバーは利用できる。

## 取得範囲とポーリングの停止

地図を動かした後の「このエリアを読み込む」で要求範囲を更新する。航空機はサーバーで中心緯度・経度を0.1度刻みに丸め、半径を5海里単位で切り上げる。この値をキャッシュキー・上流への要求・応答の`coverage`へ共通に使い、フッターにも応答の半径を表示する。近接した利用者は同じ210秒キャッシュと実行中の取得を共有する。

航空機の上流取得は、共有予算ごとに最短210秒（3分30秒）空ける。別エリア・別タブ・有料セッションも同じ予算の取得枠を使い、手動更新や再接続で連続消費できない。キャッシュがあれば上流を呼ばずに返す。枠の待機中は、同じ範囲の観測から5分以内のデータだけSTALEとして表示し、利用できるデータがなければ空配列と`reason: budget-paced`を返して「更新待機」と表示する。

航空機応答の`nextRefreshAt`はUTCの次回時刻、`nextRefreshAfterMs`はサーバーの応答処理時点からの相対待機時間。クライアントは相対時間を優先し、端末時計のずれで早く取得したり、さらに210秒待ったりしないようにする。既存キャッシュを途中から利用した場合は、その残り時間に合わせる。HTTP 429の`retryAfterSeconds`が長ければ通常間隔より優先し、範囲変更・再開・再接続でも待機を守る。

`GET /api/v1/ships`と`GET /api/v1/cameras`はいずれも`lat`・`lon`・`radius_nm`（1〜250）が必須。不正値・省略は400。Fintrafficの全件カタログは従来どおりサーバーで共有し、応答時に中心からの大円距離で要求円内だけを返す。`coverage`は要求円、`message`はフィンランドの受信範囲を示す。

取得を省略する概略矩形は船舶が北緯53〜70度・東経9〜33度、カメラが北緯59〜71度・東経19〜32度。要求円と矩形が交差しなければ、ブラウザーは取得せず「対象範囲外」と表示する。サーバーも上流へ接続せず、空配列と`reason: outside-coverage`を返す。矩形内でも受信を保証せず、円が境界に触れる場合は取得を許す。根拠は[公式の船舶対象範囲](https://www.digitraffic.fi/en/marine-traffic/)・[フィンランド道路のカメラ仕様](https://www.digitraffic.fi/en/road-traffic/)と、2026-10-15に各1回だけ取得した分布（直近船舶602隻: 北緯57.67〜65.80度・東経18.44〜32.53度、カメラ813地点: 北緯59.86〜70.09度・東経19.62〜31.28度）で、標本より余裕を持たせている。AISStreamとユーザー登録のYouTube配信にはこの制限を適用しない。

表示中の定期取得は航空機が通常210秒、天気メタデータ・船舶が60秒、雲が5分（サーバーキャッシュは30分）、衛星が10分、カメラが1時間。`document.visibilityState`が`hidden`の間は全レイヤーのAPIポーリングを停止し、進行中のブラウザーリクエストも中止する。上流ですでに始まった取得の消費は取り消せない。復帰時は各レイヤーの次回時刻を過ぎていれば1回だけ更新し、過ぎていなければ残り時間を待つ。見逃した回数分の取得は行わない。画像タイルや動画の再生制御を変更するものではない。

航空機だけはポインター・キー・ホイール・タッチ操作が15分ないと自動更新を停止し、ヘッダーへ「自動更新を一時停止中・再開」を表示する。操作または再開ボタンでキャッシュの取得を再開するが、429待機と上流の取得枠は守る。タブへの復帰も利用再開として扱う。鮮度判定は取得間隔と分離し、観測時刻から1分超はSTALE、5分超は航空機を非表示にする。最初の上流応答も同じ基準で検証し、不正な時刻・1分を超える未来時刻は採用しない。予測移動の既存150秒上限は延ばさないため、次の実観測まで一時的に動きが止まる区間がある。

航空機1タブ・同じ範囲の試算（変更前は1分間隔、変更後は3分30秒間隔。上限・キャッシュ命中を適用する前の取得需要）:

| 状態 | 改善前の上流取得機会/日 | 改善後の上流取得機会/日 |
| --- | ---: | ---: |
| 24時間表示し、操作を続ける | 1,440 | 412 |
| 初回表示後に操作せず放置 | 約15 | 約5（0・3.5・7・10.5・14分） |
| 初めから24時間非表示 | 0 | 0 |

同じ共有予算のUTCの1日では、範囲を変えて要求し続けても210秒の枠は最大412回で、450回の上限まで38回の余裕がある。キャッシュ命中・失敗待機ではさらに少なくなる。一方、離れた複数エリアは同じ枠を競合するため、待機や5分超の空表示が起こり得る。本番では予算をCloud Storageへ永続化し、同じ取得元の枠を複数地域・インスタンス・再起動で共有する。保存待ちの時間も鮮度判定に含める。

## 航空機予算の永続化と復旧

`FLIGHT_BUDGET_PREFIX=gs://bucket/prefix`を全地域へ共通設定する。省略時は既存のCloud Storage版`ORBIT_CACHE_PATH`と同じディレクトリの`aircraft-budget/`を使う。既存の2地域では`gs://gen-lang-client-0867951986-orbit-cache/aircraft-budget/`以下に`adsb.lol.json`、`airplanes.live.json`、`adsbexchange.json`を置く。衛星の`orbits.json`・形式・取得頻度・失敗ラッチは変更しない。非公開の既存バケットと実行サービスIDを使い、全地域のIDに対象オブジェクトの読み書き権限が必要。新しいキーやブラウザー側の設定は不要。

各取得元の台帳は`version`、UTCの`day`、`count`、`nextRequestAt`、`blockedUntil`、未完了取得IDの`pending`だけを持つ。450回/UTC日を維持し、取得前に世代一致条件でカウントと210秒の枠を確保する。複数地域の競合では勝った要求だけが上流を呼ぶ。確実な412競合だけ再読込して最大8回試し、タイムアウトなど結果不明の書込は再試行しない。上流の成功・失敗にかかわらず予約済みの1回を消費し、失敗を返金しない。完了時にも210秒以上の間隔を確保するため、実際の更新は上流やストレージの遅延分だけ長くなることがある。[Cloud Storageの世代条件](https://docs.cloud.google.com/storage/docs/request-preconditions)

429の停止期限も完了書込へ含める。標準・従来取得元のRetry-Afterなしは次のUTC日付切替、有料経路は既存の24時間停止を維持し、両方の条件がある場合は長い方を保存する。停止期限はUTCの日付切替でも消さず、カウントだけ翌日にリセットする。古い非同期処理や時計の逆行で日付・カウントを巻き戻さない。保存中に日付をまたいだ予約は、そのまま新しい日の上流取得へ流用しない。

本番（`NODE_ENV=production`またはCloud Run）では、共有ストレージ未設定・権限不足・障害・不正台帳の際に新規取得を停止する。メモリへ切り替えない。取得済みのローカルキャッシュだけは既存の鮮度上限内で表示し、5分超で消す。API応答は次回試行時刻を返すが、保存障害時の試行は上流への取得ではない。`GET /api/v1/status`は最後に観測した予算を表示するだけで、ヘルスチェックによるストレージ読書きはしない。航空機データのキャッシュ自体は従来どおり地域・インスタンス内で、キー付きの結果を他セッションへ共有しない。

**初回移行**: 旧プロセスの当日消費回数は復元できない。台帳が存在しない場合は、作成当日の450枠を安全側で予約済みとして保存し、次のUTC日付切替（日本時間9時）まで新規取得を止める。初日の`requestCount=450`は実測した上流取得回数ではなく、この移行用の予約を表す。翌日は通常の共有取得へ移る。全地域を新しい版へ切り替える必要があり、旧版が残る間の消費は台帳に集計されない。既存オブジェクトの削除・別prefixへの変更も新規台帳と同じ扱いになるので、復旧手段として使わない。

**未完了取得の復旧**: 取得前に`pending`を保存し、完了と429期限の保存が成功するまで次の取得を許可しない。プロセスが取得中に落ちた場合や書込結果が不明な場合は、翌日・再起動後もこの停止を保つ。未知のRetry-Afterを短いリースで解除しないため、管理者の確認が必要となる。

1. 対象取得元を使う全revisionの取得を止め、実行中の要求が終わったことと提供元の429・停止期限を確認する。不明なら再開しない。
2. 対象オブジェクトの現在の内容と世代番号を取得し、調査用に保存する。公開バケットやクライアントへ内容を送らない。
3. 日付・カウント・次回取得時刻を減らさず、`blockedUntil`を確認済みの停止期限以上に保ったまま、`pending`だけを`null`へ変更する。台帳が壊れている場合はバックアップなどで安全に復元できるまで取得を止める。
4. 管理者の修正も取得した世代番号を条件に書き込む（例: `gcloud storage cp repaired.json gs://bucket/prefix/adsb.lol.json --if-generation-match=GENERATION`）。競合したら上書きせず再調査する。全地域を同じprefixで再開する。

認証情報・キー・接続トークン・航空機の観測データは台帳へ保存しない。ローカル開発でCloud Storageのprefixがない場合だけ従来のメモリ予算を使い、ローカルファイルを分散CAS対応の永続台帳とみなさない。

## APIキーを設定する

画面右側の「表示設定」→「ライブデータ接続」で取得元を選び、キーを入力して「接続設定を適用」を押す。設定の保存は接続成功の証明ではなく、実際の取得結果を各ライブレイヤーに表示する。

- **AISStream（無料・キーが必要）**: [公式サイト](https://aisstream.io/)でGitHubアカウントを使ってキーを作成する。「船舶」でAISStreamを選択して入力し、ライブベータで船舶をオンにして現在のエリアを読み込む。[公式仕様](https://aisstream.io/documentation)はブラウザーからの直接接続を禁止しているため、サーバーからWebSocketで接続する。受信局に依存し、世界の全船舶を保証しない。非接続・拒否時には再設定が必要。
- **ADS-B Exchange / RapidAPI（有料）**: [公式Developer Hub](https://www.adsbexchange.com/community/developer-hub/)から[RapidAPIのプラン](https://rapidapi.com/adsbx/api/adsbexchange-com1/pricing)を確認・契約する。「航空機」で選択してRapidAPIキーを入力する。契約や支払いはアプリ内で行わない。リクエスト数・帯域の超過料金があり得るため、現行プランを確認する。キー付きの実取得は未検証。
- **Airplanes.live（従来の取得元）**: 選択肢を残したが、今回の実取得ではHTTP 403だった。成功するものとして扱わない。

キーは同一オリジンのPOST本文で送り、サーバーのメモリに最大1時間だけ保持する。ブラウザーのsessionStorageには不透明な接続トークンだけを保持する。切断・期限切れでキーを破棄し、待機中・実行中の有料取得を停止する。期限切れに別の取得元へ黙って切り替えない。サーバー再起動後は再入力する。HTTPSまたはlocalhostが必要。

標準adsb.lolのキャッシュ・取得上限は利用者間で共有する。従来のAirplanes.liveは別の共有サービス、有料取得はセッション別キャッシュ・全有料セッション共通の予算を使う。各既存予算の450回/日を維持し、210秒の取得枠を共通化する。提供元の1秒間隔制御も残し、HTTP 429の待機時間を再接続でリセットしない。提供元の月間課金上限を保証するものではない。

YouTubeは表示設定の「公開YouTube配信」へ動画URL・名前・緯度・経度を入力する。APIキーは不要。配信元を開くリンクは常に残す。動画の選択・再生・広告配信はYouTube側が管理し、制作者の収益をこのアプリが保証するものではない。[公式埋め込み仕様](https://developers.google.com/youtube/player_parameters)

## 衛星キャッシュの運用

ローカルでは`.cache/orbits.json`を使用する。起動後もこのファイルを維持する。CelesTrakはGP/SupGPの取得を2時間以上空け、非200応答後は人が原因を調査するまで自動取得を止めるよう求めている。[利用方針](https://celestrak.org/usage-policy.php)

本番環境では、永続ストレージ上のパス、または`gs://bucket/object`を`ORBIT_CACHE_PATH`へ設定しない限り、衛星の自動取得を開始しない。Cloud Runのコンテナ内一時ファイルは永続ストレージとして扱わない。Cloud Storageでは既存の実行サービスIDで認証し、同じオブジェクトの世代番号を条件にして更新権を取得する。2地域・新旧revisionが重なっても、更新権を得たサーバーだけがCelesTrakを取得する。正常なキャッシュは2時間メモリーにも保持し、画面のポーリングごとにCloud Storageから全要素を再転送しない。[世代条件の仕様](https://docs.cloud.google.com/storage/docs/request-preconditions)

既存Cloud Run公開先は`asia-northeast1`と`us-west1`。`gs://gen-lang-client-0867951986-orbit-cache/orbits.json`を共通の非公開キャッシュにする。東京側はリポジトリのCloud Build設定、西側は別の既存トリガーを使用する。ストレージは公開せず、APIキーも保存しない。デプロイ後の確認結果は[PR #22](https://github.com/lingmulongtai/AeroGrid-3D/pull/22)へ記録する。

キャッシュに`blocked`が記録された場合は、HTTPエラー・提供元の告知・ネットワークを確認し、問題を解消した後に管理者がその項目を削除する。自動で解除しない。レスポンス時刻やキャッシュが壊れている場合も自動取得を止める。

### 衛星APIの配信

`GET /api/v1/satellites?limit=N`は整数1〜5000件、省略時1200件を返す。不正値は400。画質ごとに300 / 1200 / 2400 / 4200件を指定し、SGP4と表示・検証に必要な14項目だけを送る。永続キャッシュの全要素・保存形式・2時間間隔・停止ラッチ・Cloud Storage世代条件は変更しない。

選択順はキャッシュの`fetchedAt`世代ごとに一度計算する。その世代の取得時刻に対して14日超過・24時間超の未来・SGP4失敗の要素を除外し、クライアントも表示時刻で安全確認を続ける。ISS（25544）、天宮（48274）を先頭に置き、その後はStarlink、OneWeb/Iridium、航法、静止軌道、その他を母数比率の重み付きラウンドロビンで混ぜる。各カテゴリの最低重みは2%。分類条件は従来と同じで、「その他」の内部名は`earth-observation`だが、全件が地球観測衛星と確認されたわけではない。カテゴリ内はNORAD昇順の区間中点を幅優先で取り出し、小さい件数でも番号範囲全体へ分散させる。どのlimitも同じ順序の先頭部分となる。

衛星APIだけ`Cache-Control: public, max-age=残り秒数`を使う。残り秒数は`expiresAt`まで、最小0・最大600秒。強いETagは取得世代・limit・状態やメッセージ・圧縮形式と実際の本文を識別し、`If-None-Match`の一致は本文なしの304になる。`Vary: Accept-Encoding`を付け、`unavailable`は`no-store`で配信する。サーバーはJSONとgzip/Brotli結果を世代・limitごとにメモ化し、任意のlimit指定でメモリが増え続けないよう最近使った16種類まで保持する。

衛星の10分ポーリングとカメラの1時間ポーリングは表示中のみ継続する。接続設定などの`refreshToken`だけではこの2カタログを再取得しない。カメラは読み込む中心・半径の変更時に要求円で再取得する。衛星は画質変更時に新しいlimitで取得し、同じ世代・件数またはETagならstateと要素配列を保持してメッシュ再構築を避ける。船舶・雲のエリア更新は従来どおり。

APIのJSONと静的JS/CSS/JSON/SVGはgzip/Brotli対応、PNG/JPGは対象外。通常の圧縮は`compression`の既定値、衛星の保存済み表現もgzipレベル6・Brotli品質4を使用する。

## 取得元の比較と根拠

- **adsb.lol**: ODbL 1.0。商用利用にもライセンス条件がある。無料APIに固定の数値上限は公表されておらず、本番利用は運営者への相談が求められる。[仕様・ライセンス](https://www.adsb.lol/docs/open-data/api/)、[公式OpenAPI](https://api.adsb.lol/api/openapi.json)。ブラウザー向けCORSヘッダーが今回の応答にないため、サーバー経由で取得する。
- **Open-Meteo GFS**: 高度変数はメートルAMSL、雲量は各気圧面のモデル雲量。地表気圧より下、地面より低い高度を除外する。無料APIは非商用・日10,000回未満、時間5,000回、分600回の条件がある。多地点・変数数による計算も考慮する。[高度・雲量の仕様](https://open-meteo.com/en/docs/gfs-api)、[利用条件](https://open-meteo.com/en/terms)。データはCC BY 4.0。
- **CelesTrak**: 新しい6桁のカタログ番号も扱えるOMM JSONを採用。[フォーマット](https://celestrak.org/NORAD/documentation/gp-data-formats.php)。SGP4の実装はMITライセンスの[satellite.js](https://github.com/shashwatak/satellite-js)。軌道予測の誤差は要素の古さ・機動・抗力などに依存する。
- **Fintraffic**: CC BY 4.0。船舶の地域範囲・除外対象を明示する。[船舶API](https://www.digitraffic.fi/en/marine-traffic/)、[AIS対象条件](https://www.digitraffic.fi/en/marine-traffic/ais/)、[カメラAPI](https://www.digitraffic.fi/en/road-traffic/)、[利用条件](https://www.digitraffic.fi/en/terms-of-service/)。
- **OpenSky**: 現在の利用規約では、運用サービスへREST APIを組み込む前に書面の利用契約が必要。無料枠があるだけでこの製品へ自動導入できるわけではない。[利用規約](https://opensky-network.org/about/terms-of-use)、[API仕様](https://github.com/openskynetwork/opensky-api/blob/master/docs/free/rest.rst)。今回は導入しない。
- **RainViewer**: 雲高度や3D雲の観測ではない。[公式API](https://www.rainviewer.com/api.html)。

God's Eye Viewは公開ソースをサーバーで集約する設計が参考になる。ただし[README](https://github.com/bilawalsidhu/gods-eye-view)は交通・車を実際の道路に沿ったシミュレーションと明記している。[車の描画コード](https://github.com/bilawalsidhu/gods-eye-view/blob/main/src/layers/traffic/animation.js)にもランダム配置・移動がある。個々の実車のライブ追跡として移植しない。[新宿カメラ設定](https://github.com/bilawalsidhu/gods-eye-view/blob/main/config/cctv_sources.shinjuku.json)には投影テスト用のサンプル動画も含まれるため、公開カメラの実配信と区別する。

## 今回の実接続確認

2026-10-13のローカルサーバー経由で、航空機130件、軌道要素16,693件、GFSの9地点、5分以内の船舶657件、カメラ812地点を取得した。これらはその時点の標本であり、恒常的な件数・完全な網羅性・外部APIの可用性を保証しない。

AISStreamと有料ADS-B Exchangeは仕様・接続経路・キーの分離・期限切れ・429待機をテストしたが、利用者の有効なキーによる実接続はまだ確認していない。YouTube動画の配信権限・ライブ状態も動画ごとに配信元で確認する。
